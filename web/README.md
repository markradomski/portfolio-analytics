# Portfolio frontend

Phase 5.1–5.4: the foundation, design system, chart system and data-quality
system, per the phased spec. Screen content (5.5 onward — Overview,
Performance, Holdings, etc.) is intentionally not built yet; every route
exists and renders inside the app shell, but shows a placeholder except
`OverviewPage`, which is a small proof that the full stack connects end to
end against the real API.

## Running it

```bash
# Terminal 1 — the API (from the project root, not web/)
./venv/bin/uvicorn src.api.app:app --port 8000

# Terminal 2 — the frontend
cd web && npm run dev
```

```bash
npm run test         # Vitest, 100 tests
npm run typecheck    # tsc --noEmit
npm run storybook    # component library
```

## Architecture

```
API (FastAPI, src/api/)
  ↓ HTTP, Decimal-as-string
src/api/client.ts + portfolio.ts + analytics.ts   -- the only place fetch() is called
  ↓
src/hooks/api/                                     -- React Query wrappers
  ↓
src/features/*                                     -- screens (App owns routing/composition)
  ↓
src/design-system/ + src/components/charts/ + src/components/data-quality/
```

Nothing above the API adapter imports `src/engine` or `src/history` — there
is no Python to import from the frontend at all; the HTTP boundary is the
only connection. No component recalculates a return, a gain, a cost basis or
an allocation weight. If a screen needs a figure the API doesn't expose yet,
the fix is a new endpoint in `src/api/app.py`, never a calculation in React.

## Generated types

`src/api/schema.generated.ts` is generated by `openapi-typescript` from the
API's own OpenAPI schema, which now carries a real per-endpoint Pydantic
`response_model` (`src/api/models/`, see `docs/api.md`) instead of the
generic `JSONResponse` this project started with. `src/api/types.ts` is a
thin `export type X = components["schemas"]["X"]` alias layer on top of
that generated file — one alias per response model, keeping the names the
rest of the frontend already imports stable across a regeneration.
`src/api/__tests__/contract.test.ts` still checks captured fixture
responses (from the synthetic test database, never real portfolio figures)
against `types.ts`'s field names, as a second, independent guard against
drift. See `docs/api.md` for the exact regeneration commands.

## Design system

Tokens in `src/design-system/tokens.css` — colour, typography, spacing,
radius, shadow, motion, plus a distinct token set for data-quality tones
(actual/calculated/estimated/limited/unavailable) kept separate from the
gain/loss tones, since "estimated" is a fact about provenance, not a warning
about performance. Dark mode redefines the same token names; no component
branches on theme itself.

## Chart system

D3 owns scales, paths, geometry and interaction math; React owns state,
composition and when things re-render (`ChartContainer` measures width via
`ResizeObserver` and hands `{width, height}` to a render-prop; `Axis` is the
one place a D3 selection touches the DOM directly, imperatively, since
d3-axis has no declarative equivalent worth reinventing).

Every time-series chart shares one hover convention
(`hooks/useNearestPoint.ts` — pointer move → nearest point by
`d3.bisector` → crosshair → tooltip), so `TimeSeriesChart` and
`DrawdownChart` behave identically to hover rather than each inventing their
own pointer math.

`TimeSeriesChart` is the one place data-quality fidelity actually matters
visually: a series is split into contiguous runs by `valuation_status`, an
`estimated` (carried-forward) run renders thinner, lighter and dashed, and a
`null` value breaks the line rather than being plotted as zero. A run only
one point long — common at a quality boundary — renders as a dot rather than
being silently dropped; this was a real bug caught by
`TimeSeriesChart.test.tsx`, not a hypothetical.

`AllocationChart` deliberately isn't a pie chart (sec 17): a single
proportional bar plus a legend table keeps exact value and weight legible
per segment, which a pie chart's angle comparison loses.

## Data-quality system

`DataQualityBadge`, `DataCoverageBadge`, `LimitedDataNotice`,
`UnavailableMetric`, `MethodologyPopover` are the only places a `DataQuality`
value or a capability's `available`/`reason` becomes visible UI.
`useCapabilityTabs` turns a period label list into `Tabs` items whose
disabled state and reason come entirely from `getAnalyticsCapabilities()` —
never a frontend rule like `if (years < 1)`.

## Real bugs found while building this

- **CORS was hard-coded to port 5173.** Vite picks the first free port from
  5173 upward; with something else already listening on 5173/5174 (common in
  a long dev session), the app silently ran on 5175 and every request was
  blocked. Fixed with an origin regex matching any localhost port in
  development, caught by actually running the app against the real API
  rather than trusting the API tests alone.
- **`ReconciliationResult.computed_closing`** (a backward-compat alias added
  during the Phase 4 hardening pass) was wrong — `attributed_change` already
  *is* the computed closing value for `reconcile_growth`, so the alias
  re-added `opening + flows` on top of it, producing a nonsense figure
  ($130,027 against a real closing value of $68,195). Caught via the API
  response while wiring this layer up, not by inspection — nothing in the
  codebase had ever actually called it. Removed.
- **`role="button"` on a sortable `<th>`** erased its native `columnheader`
  semantics from the accessibility tree — exactly the kind of regression
  sec 32 exists to prevent. `aria-sort` is the correct ARIA pattern for a
  sortable header; fixed to use that instead, caught by a test that queries
  for the `columnheader` role and found it missing.

## Known gaps at the end of 5.1–5.4

- No visual regression tooling wired up yet (Chromatic or equivalent) — sec
  51 is deferred until there's enough real screen content for a baseline to
  mean something.
- (Resolved in the API contract hardening pass) `schema.generated.ts` is
  now generated from real per-endpoint Pydantic `response_model`s and is
  what `types.ts` aliases — see `docs/api.md`.
- Accessibility has been built in from the start (semantic HTML, ARIA on
  interactive elements, keyboard operability, non-colour-only encoding on
  every badge) but has not had a dedicated audit pass yet — that's explicitly
  scheduled for 5.13 (Polish) once there are real screens to audit.
